# AURA V3.4 — Release and Verification Checklist

V3.4 is a development milestone, not a claim that the production site has been deployed or independently audited.

## Included

- Shared responsive design layer for the main site and new standalone pages.
- Product overview page describing current assets separately from future platform layers.
- Developer onboarding page with local setup, API surface, contribution principles and open engineering work.
- Public system status page backed by `GET /api/health`.
- Improved main navigation, metadata, keyboard skip link and focus styling.
- Baseline HTTP security headers, disabled Express signature header, bounded JSON request bodies and no-store API responses.
- Node built-in smoke tests and GitHub Actions quality workflow.

## Local verification

1. Use Node.js 20 or newer.
2. Run `npm ci`.
3. Run `npm test`.
4. Run `npm run check`.
5. Run `npm start`.
6. Verify:
   - `/`
   - `/product.html`
   - `/developer-guide.html`
   - `/status.html`
   - `/brief.html`
   - `/faq.html`
   - `/api/health`
   - `/api/status`\n   - `/sitemap.xml`\n   - `/robots.txt`\n   - Unknown `.html` paths display the branded 404 page.
7. Confirm unknown file paths return 404.
8. Test at desktop width and at 390px / 320px mobile widths.
9. Test keyboard-only navigation, visible focus, reduced-motion preference and mobile menu.
10. With MetaMask installed, test connect, disconnect, account change, chain change, ETH balance display and read-only NFT ownership check. Do not sign an identity challenge unless you intend to create the optional off-chain identity record.

## Important boundaries

- No changes are made to the main branch, DNS, hosting configuration or live deployment.
- No wallet transaction is requested by the read-only ownership check.
- Identity data remains off-chain and requires a configured database.
- The token/economic layer remains research only; no token contract or sale is claimed.
- HTTP headers are baseline hardening, not a substitute for a threat model, dependency review, penetration test or independent security audit.
- The public health endpoint exposes integration availability only; it does not provide a service-level guarantee.

## Before production release

- Run the complete local and CI checks.
- Confirm all optional integrations in the target environment.
- Review reverse-proxy behavior and HTTPS configuration.
- Review CSP requirements before enforcing a Content Security Policy; current frontend uses inline scripts/styles and injected wallet providers.
- Add durable rate limiting and abuse monitoring if public API usage warrants it.
- Confirm backups, database migrations, monitoring and incident response.
- Obtain independent security review for identity and wallet-related flows.
- Review all investor, token, fundraising and compensation language with qualified counsel where applicable.
