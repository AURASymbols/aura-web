AURA / DEVELOPER ONBOARDING

Inspect first.
Build with intent.

AURA is an early-stage project. The repository contains a Node.js and Express web foundation, a lightweight browser frontend, an initial NFT catalog and optional Ethereum and database integrations. The complete platform is not yet deployed.

OPEN GITHUB ↗CONTRIBUTION AREAS
01 / LOCAL SETUP

Run the public foundation.

The website is designed to start without private credentials or a database. Optional features can be enabled separately.

git clone https://github.com/AURASymbols/aura-web.git
cd aura-web
npm install
npm start

# Open http://localhost:3000
Use Node.js 20 or newer. Keep your local .env file private. Never commit RPC keys, database credentials, wallet secrets or API tokens.
02 / STACK & MODULES

Understand the current foundation.

FRONTEND

HTML / CSS / JavaScript

Vanilla JavaScript and a responsive single-page portal. Hash-based sections currently power the main site.

BACKEND

Node.js / Express 5

Static serving, project status, health, wallet balance, NFT catalog and identity API foundations.

WEB3

ethers.js v6

Ethereum RPC reads, wallet connection through an injected provider and read-only ERC-1155 ownership checks.

DATA

PostgreSQL / pg

Database-backed identity association is optional and requires a separately configured database.

03 / API SURFACE

Current public endpoints.

METHODPATHPURPOSE
GET/api/healthService, database and Ethereum connectivity status.
GET/api/statusPublic project stage and system summary.
GET/api/wallet/:addressRead-only ETH balance lookup when RPC is configured.
GET/api/nftsCurrent AURA NFT catalog.
GET/api/nfts/verify?address=...Read-only ERC-1155 ownership verification on Ethereum mainnet.
GET/api/identity?address=...Look up an off-chain identity record when database storage is configured.
GET / POST/api/identity/challenge / /api/identityWallet-signature challenge and off-chain identity association flow.
The API surface is an initial foundation, not a production service-level commitment. Identity records are off-chain. The NFT verification endpoint performs read-only checks and does not submit transactions.
04 / CONTRIBUTION PRINCIPLES

Small, reviewable, verifiable.

01 / PROPOSE

Explain the problem

Describe the user need, current behavior and expected outcome before introducing a new system.

02 / IMPLEMENT

Keep changes focused

Prefer small modules, clear boundaries, accessible interfaces and documented assumptions.

03 / VERIFY

Show the evidence

Include reproducible test steps, known limitations and screenshots or logs where useful.
